# 05-theory_check（子 agent 视角）

## 具体怎么干

### 对抗式审查（不是确认式）
假设有错，去找错。分两路：

**物理→公式**：
- 公式解的是不是论文的物理问题
- 边界条件对不对（切向 vs 法向）
- 假设有没有偷偷加

**公式→代码**：
- 代码实现的是不是公式说的
- 特殊函数调用对不对（球贝塞尔 vs 普通）
- 级数截断够不够
- 单位一致吗

### 问题分级
- **致命**：公式错——必须修，回 step 04
- **重要**：实现偏差——要修
- **轻微**：风格——记下来

### 预制脚本（scripts/）
- `check_formula_against_textbook.py` — 把代码里的 $a_n, b_n$ 和教材公式做符号对比（如能做）

## 输出约定

- 审查报告：`.work/.todo/{paper}/{case}/theory_check.md`
- 修正后的推导/代码（如需）

## 常见坑

- 别因为"能跑"就放过——能跑不代表对
- 双向归因每一步都要对上，跳一步可能漏错
- 对抗式不是挑刺，是真的假设有错去找

## 人工 gate ③

这步末停下来，让用户对着教材核 $a_n, b_n$。你在报告里附上你核对的公式和教材页码，方便用户复核。
