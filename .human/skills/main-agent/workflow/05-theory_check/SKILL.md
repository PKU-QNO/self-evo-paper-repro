# 05-theory_check（主 agent 视角）

## 这步干什么

对抗式审查推导和代码。双向归因：①从物理到公式——公式解的是不是论文的物理问题；②从公式到物理——代码实现的是不是公式说的。

## 输出要求

- 审查报告（`.work/<case>/theory_check.md`）：
  - 公式逐条核对（对照教材）
  - 代码逐条核对（对照公式）
  - 发现的问题清单
  - 修正建议
- 修正后的推导和代码（如需）

## 要传达给子 agent 的约定

- 审查要**对抗式**，不是确认式。假设有错，去找错。
- 双向归因：物理→公式→代码，每一步都要能对上
- 找到的问题要分级：致命（公式错）/ 重要（实现偏差）/ 轻微（风格）
- 不能因为"能跑"就放过

## 本步子 agent 必须回答的决策问题

1. 公式和教材一致吗？哪些有出入？
2. 代码实现的是公式说的吗？有没有偷工减料？
3. 有没有"正确解了错题"的风险（公式对但解的不是论文问题）？
4. 修正后可以进 step 06 运行了吗？

## 人工 gate ③

**关键公式推导后停下来**，让用户对着教材核 $a_n, b_n$。这是最关键的 gate，错了后面全错。
